## 1. 簡介與工具定位

### 1.1 為什麼需要此模擬器？
在核酸檢測自動化儀器中，大陸團隊所開發的**底層影像識別模組**與台灣團隊開發的 **GUI 使用者介面 (`TRIOV2.App`)** 是共同運行在同一台 Windows 11 Pro IoT 工控機上。

根據大陸團隊提供的基準規格：
- **CPU 基準**：Intel Core i7-9700K (8C8T)。
- **影像規格**：解析度 $4656 \times 3496$（約 1,628 萬像素），檔案約 **270 MB**。
- **運算負載**：CPU 佔用約 **12% ~ 15%**（等效於 1.0 ~ 1.2 顆核心滿載）。

當底層進行大尺寸影像解析時，CPU 的瞬間計算與高頻率存取 270MB 緩衝區（搶佔記憶體匯流排頻寬與 L3 快取），極易造成前景 GUI（WPF 渲染執行緒、觸控回饋、動畫）產生掉幀或微卡頓。

本模擬器專門用來**在真實硬體或開發機上 100% 重現底層影像識別模組的 CPU/記憶體/匯流排壓力**，讓您在不需要底層相機與真實影像演算法的情況下，驗證前景 GUI 在各種極限負載下的順暢度與剩餘資源。

### 2.1 頂部功能列
- **視窗置頂 (Always On Top)**：預設勾選。讓模擬器永遠浮在最上層，便於操作 `TRIOV2.App` 時隨時監看波形圖。

### 2.2 效能指標卡片 (免開工作管理員)
- **CPU (處理器) 卡片**：
  - **總 CPU %**：全系統當前實際處理器使用率。
  - **模擬器產出負載**：模擬器自身所產生的 CPU 負載。
  - **系統剩餘可用 (Idle %)**：作業系統當前閒置率（綠色字體）。若此值接近 0%，代表系統已無餘力處理 UI 互動。
- **記憶體 (RAM) 卡片**：
  - **已用 / 總容量**：目前系統實際佔用的實體記憶體（例如 `8.4 / 16.0 GB (52%)`）。
  - **系統可用記憶體**：未使用的實體 RAM（例如 `7.6 GB`）。
  - **模擬影像緩衝 (WorkingSet)**：本模擬器為 4656×3496 影像分配並常駐的實體記憶體（預設 270 MB）。

## 3. 三大測試模式與實戰操作教學

### 模式一：單次拍圖辨識觸發 (Single-Shot) ⭐ **【主力推薦：最符合真實工況】**
- **真實設備工況**：核酸檢測機台將試劑盤送入定位後，相機拍下一張高解析照片（270MB），底層模組啟動辨識，運算 0.8 秒後結束，判定耗材擺放是否正確。
- **操作步驟**：
  1. 運作模式勾選 **`(●) 單次拍圖辨識 (Single-Shot)`**。
  2. 此時模擬器處於待機狀態（CPU 0%），270 MB 緩衝區已就緒。
  3. 啟動您的主程式 [`TRIOV2.App.exe`](file:///d:/TRIOV2/src/TRIOV2.App/bin/Debug/net8.0-windows/TRIOV2.App.exe)。
  4. 當您在 `TRIOV2.App` 上滑動清單、點擊按鈕、展開對話框或播放動畫時，同時點擊模擬器上的 **`[ 📸 模擬拍圖並執行辨識 ]`**。
  5. **觀察重點**：
     - 波形圖會瞬間衝出一個 15% 的脈衝波峰，並在 800ms 後平穩回落。
     - 檢查 `TRIOV2.App` 是否有畫面頓挫、觸控點擊延遲或按鈕反應慢半拍的狀況。

### 模式二：週期連續排程辨識 (Periodic Batch)
- **真實設備工況**：自動化流水線連續檢驗多個樣本架，每隔幾秒連續拍圖一次。
- **操作步驟**：
  1. 運作模式勾選 **`(○) 週期連續排程 (Periodic)`**。
  2. 點擊 **`[ ▶ 啟動排程 ]`**。
  3. 模擬器會每隔 3 秒自動執行一次拍圖辨識（波形圖會呈現規律的鋸齒脈衝）。
  4. 隨時點擊 **`[ ⏹ 停止 ]`** 可停止排程。
  5. **觀察重點**：連續運作數分鐘，觀察工控機是否有 CPU 降頻、溫度過高或系統剩餘可用記憶體持續下降的異常現象。

### 模式三：極限連續高壓模式 (Continuous Stress)
- **真實設備工況**：探測工控機在演算法演進或背景極限運算時，GUI 的崩潰臨界點。
- **操作步驟**：
  1. 運作模式勾選 **`(○) 極限連續高壓 (Continuous)`**。
  2. 模擬器會持續恆定輸出所設定的 CPU 與記憶體負載。
  3. 隨時拖動 **「CPU 目標佔用滑桿」**（例如從 15% 逐步拉到 30%、50%、80%、95%）。
  4. **觀察重點**：找出 CPU 佔用到多少百分比時，`TRIOV2.App` 會開始出現肉眼可見的掉幀與觸控卡頓。

## 4. 參數調整與快速預設情境

### 4.1 滑桿說明
- **CPU 目標佔用 (0% ~ 100%)**：微調模擬負載。
- **影像記憶體緩衝 (50MB ~ 4096MB)**：調整影像資料緩衝區大小。
- **辨識運算耗時 (100ms ~ 3000ms)**：單次拍照後，底層模組辨識持續的時間（預設 800ms）。

## 5. 常見問題與高負載說明 (FAQ)

### Q1：為什麼之前拉到 90% 時程式會突然關閉？是作業系統保護嗎？
**答：不是作業系統保護，而是 .NET 執行環境的「單一陣列 2GB 上限與 32-bit 整數溢位」問題，現已全面修復！**
- **原因剖析**：
  滑桿最大值為 4096 MB（4 GB）。當拉到 90%（約 3,686 MB）時，原程式碼以 32-bit `int` 計算位元組數（$3686 \times 1024 \times 1024$），數值超過了 32-bit 整數最大值 $2,147,483,647$ (2GB)，產生了整數溢位（變成負數），且 .NET 原生限制單一陣列長度不得超過 2GB，因而觸發例外退出。
- **修復機制 (v2.1)**：
  1. **分塊記憶體架構 (Chunked Buffers)**：改為由多個 128 MB 的記憶體分塊組成，可安全無限制配置 50MB ~ 8192MB (8GB)，徹底消除 2GB 陣列溢位限制。
  2. **物理記憶體 OOM 熔斷保護**：若電腦實體可用記憶體不足，自動安全鎖定在最大可配置容量，絕不崩潰。
  3. **防抖機制 (Debounce)**：滑動滑桿時加入 250ms 防抖，避免快速拖曳時瞬間產生數百次大記憶體重新配置。
  4. **全域例外攔截**：加入視窗錯誤提示保護，不再靜默閃退。

### Q2：測試時系統剩餘多少 CPU 與 RAM 算安全？
- **CPU 剩餘可用 (Idle %)**：建議維持在 **25% 以上**。低於 15% 時，WPF 的 UI 訊息泵容易出現排隊延遲（點擊無即時反饋）。
- **可用實體記憶體 (Available RAM)**：建議維持在 **2.0 GB 以上**。低於 1.0 GB 時，Windows 會啟動分頁檔 (Pagefile) 虛擬記憶體交換，導致磁碟 I/O 暴增，造成介面嚴重卡死。
