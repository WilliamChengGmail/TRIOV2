## 核心定位

| 目錄 | 定位 | 版控 |
| :--- | :--- | :--- |
| `src\Tools\` | **開發區**：自研工具與腳本的原始碼 | 受版控管理 |
| `Tools\` | **可攜執行區**：可直接複製到任何裝置運行的成品（角色等同 `bin\`） | 僅存放成品，不放原始碼 |

## 放置位置

| 類型 | 放置位置 | 說明 |
| :--- | :--- | :--- |
| 自研工具原始碼 / 專案 | `src\Tools\<工具名稱>\` | 例如：`src\Tools\PerfSimulator\` |
| 腳本原始碼（開發、建置、維運皆含） | `src\Tools\Scripts\` | 所有腳本的**唯一原始位置** |
| 執行時需要的腳本 | `Tools\Scripts\` | 僅放「工具在目標裝置上運行時會呼叫」的腳本，由 `src\Tools\Scripts\` 發佈而來 |
| 可執行檔 / 相依檔案 / 資料夾 | `Tools\` | 執行檔、DLL、設定檔、資源等 |

## 腳本歸屬判斷

- 只在開發/建置/測試階段使用（如打包、產生程式碼、CI 腳本）→ **只放** `src\Tools\Scripts\`，**不得**出現在 `Tools\`。
- 工具在目標裝置運行時需要（如啟動腳本、執行期輔助腳本）→ 原始碼在 `src\Tools\Scripts\`，發佈副本放 `Tools\Scripts\`。
- `Tools\Scripts\` 內的檔案視為發佈產物，**不得直接修改**；一律改 `src\Tools\Scripts\` 後再重新發佈。

## Tools\ 可攜性原則（強制）

`Tools\` 內所有檔案與目錄的存在目的，是讓使用者在**任何裝置**上只需複製其中**一個或多個檔案/目錄**即可運行，且**不需額外安裝任何元件**。

1. **零安裝**：不得要求目標裝置另外安裝執行環境或元件（例如 .NET Runtime、VC++ Redistributable、Python、Node.js 等）。需要的執行環境必須隨附，或以自包含（self-contained / 單檔封裝）方式建置。
2. **相依封閉**：`Tools\` 內檔案的相依關係只能指向 `Tools\` 內部，不得參照 `Tools\` 以外的路徑（含 `src\`、專案根目錄、使用者目錄）。
3. **相對路徑**：所有內部參照一律使用相對於自身位置的路徑，不得寫死絕對路徑、磁碟機代號、機器名稱或使用者名稱。
4. **不依賴環境狀態**：不得依賴 PATH、登錄檔、環境變數、全域設定或預先註冊的元件。
5. **相依可辨識**：每個工具必須附 `DEPENDENCIES.md`（詳見〈相依清單與共用相依〉），明確列出最小複製集合；專屬相依集中放在同一工具目錄下，共用相依只能放在 `Tools\Scripts\` 或 `Tools\Common\`。
6. **保持清爽**：`Tools\` 根目錄只放工具入口與必要的子目錄，不放暫存檔、建置中間檔、紀錄檔、原始碼、`.pdb` 以外的除錯產物（除非為執行所需）。

## 相依清單與共用相依（強制）

「複製一或多個檔案即可運行」的前提，是每個工具的**最小相依集合**有明確定義。因此每個工具都必須有相依清單，共用檔案也必須能反查使用者。

### 1. 相依清單（每個工具必備）

- **原始位置**：`src\Tools\<工具名稱>\DEPENDENCIES.md`（受版控，為唯一原始版本）。
- **發佈位置**：隨工具發佈至 `Tools\`，作為相依清單的副本，**不得直接修改**。
  - 工具為目錄：`Tools\<工具名稱>\DEPENDENCIES.md`
  - 工具為單一檔案：`Tools\<工具名稱>.deps.md`（此為「保持清爽」原則的唯一例外）
- 若工具為**單一自包含檔案、無任何外部相依**，清單只需寫「無外部相依」。

### 2. 清單必須載明的項目

| 欄位 | 說明 |
| :--- | :--- |
| 入口 | 使用者實際執行的檔案 |
| 專屬相依 | 僅此工具使用的檔案/目錄（相對於 `Tools\`） |
| 共用相依 | 與其他工具共用的檔案（相對於 `Tools\`），例如 `Scripts\Common.ps1` |
| 最小複製集合 | 完整列出需複製的所有路徑（入口 + 專屬 + 共用） |
| 目錄結構要求 | 複製後各檔案之間必須維持的相對位置 |

範例：

```markdown
# PerfSimulator 相依清單

- 入口：`PerfSimulator.exe`
- 專屬相依：`PerfSimulator\config.json`
- 共用相依：`Scripts\Common.ps1`、`Scripts\Start-PerfSim.ps1`
- 最小複製集合：
  - `PerfSimulator.exe`
  - `PerfSimulator\`
  - `Scripts\Common.ps1`
  - `Scripts\Start-PerfSim.ps1`
- 結構要求：`Scripts\` 必須與 `PerfSimulator.exe` 位於同一層
```

### 3. 共用相依規則

1. **集中放置**：共用檔案只能放在 `Tools\Scripts\`（共用腳本）或 `Tools\Common\`（共用函式庫/資源），不得散落於其他位置。
2. **保持相對結構**：複製單位以 `Tools\` 為根，複製時須保留相對路徑結構，不得壓平目錄。清單中的「結構要求」即為此約束的具體說明。
3. **不得隱性共用**：工具若引用共用檔案，必須列入該工具的清單。禁止「碰巧同目錄有就能用」的隱性相依。
4. **獨立工具優先**：單檔自包含的工具不得依賴共用檔案。若僅需少量共用邏輯，應於建置時內嵌，而非另外相依。
5. **共用檔案不得反向依賴**：共用檔案只能引用同為共用的檔案，不得引用任何特定工具的專屬檔案。

### 4. 異動連動規則

- **新增或修改工具**：同步更新該工具的 `DEPENDENCIES.md`，並確認清單與實際引用一致。
- **修改共用檔案**：須在實作計畫列出所有引用它的工具，逐一確認相容，並重新發佈受影響的工具及其清單。
- **反查方式**：以各工具 `DEPENDENCIES.md` 的「共用相依」欄位為依據，可由 `Build-Tools.ps1` 自動彙整產出反查表（共用檔案 → 使用它的工具）；不另外手動維護。
- **建置檢查（建議）**：`Build-Tools.ps1` 於發佈時驗證下列項目，失敗即中止：
  1. 清單所列路徑皆存在於 `Tools\`。
  2. `Tools\` 內檔案無引用清單以外的路徑，亦無引用 `src\`。
  3. 無任何 `Tools\` 檔案未被至少一份清單涵蓋（避免殘留孤兒檔案）。

## 禁止事項

- 不得將原始碼、專案檔、測試碼放入 `Tools\`。
- 不得將開發專用腳本放入 `Tools\`。
- 不得讓 `Tools\` 內檔案引用 `src\` 內的任何內容。
- 不得讓建置輸出散落於 `Tools\` 與 `src\Tools\` 以外的目錄。
- 建置/輸出未指定路徑時，一律輸出到 `Tools\`。

## 實作計畫的檔案異動清單

- 檔案路徑欄位必須符合上述規則。
- 凡異動 `Tools\` 之內容，須在「變更說明」註明其相依項目，並確認符合可攜性原則。
- 凡新增或修改工具，須同步列出其 `DEPENDENCIES.md` 的異動；修改共用檔案時，須列出所有受影響的工具。

## 範例

| 操作類型 | 檔案路徑 | 變更說明 |
| :--- | :--- | :--- |
| 新增 | `src\Tools\PerfSimulator\main.py` | 自研「效能模擬器」原始碼專案 |
| 新增 | `Tools\PerfSimulator.exe` | 自包含建置的執行檔，無需安裝執行環境 |
| 新增 | `src\Tools\Scripts\Start-PerfSim.ps1` | 啟動腳本原始碼（執行期需要） |
| 新增 | `Tools\Scripts\Start-PerfSim.ps1` | 發佈副本；僅以相對路徑呼叫 `..\PerfSimulator.exe` |
| 新增 | `src\Tools\Scripts\Build-Tools.ps1` | 建置用腳本，僅開發使用，**不**發佈至 `Tools\` |
| 新增 | `src\Tools\PerfSimulator\DEPENDENCIES.md` | 相依清單原始版本，列明共用相依 `Scripts\Common.ps1` |
| 新增 | `Tools\PerfSimulator.deps.md` | 清單發佈副本，供複製時對照最小集合 |
