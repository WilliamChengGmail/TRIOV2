# M3 介面與操作說明

日期：2026-11-12  
範圍：裝置管理、基準、場次比較、任務覆蓋矩陣、備註與標籤。

## 1. 總覽頁新增

### 1.1 基準與差異

- 「基準」欄：`★` 表示該場次是同裝置的基準。
- `ΔCPU`、`ΔRAM`：與同裝置基準的差異。
  - 正向（變高）顯示紅色。
  - 負向（變低）顯示綠色。
  - 沒有基準或不同裝置顯示 `—`。
- 基準以**裝置**為單位，每台裝置最多一個基準。

### 1.2 任務覆蓋矩陣

底部卡片提供兩個分頁：

- `列表`：原本的檢測紀錄表。
- `任務覆蓋矩陣`：列 = 場次，欄 = 任務。
  - 有執行：顯示該任務 CPU 平均，例如 `23.8%`。
  - 有任務但未執行：顯示 `未執行`。
  - 該場次沒有此任務：顯示 `—`。

## 2. 裝置管理頁

### 2.1 裝置列表

左側顯示：

- 裝置名稱／別名
- 場次數
- 基準標記 `★`

選取裝置後，右側顯示該裝置的場次。

### 2.2 編輯別名

- 在「輸入裝置別名」輸入名稱，按「儲存別名」。
- 別名會寫入該裝置所有場次的 `session.json`。
- 留空會清除別名，回到原始裝置名稱。

### 2.3 設定基準

- 在右側場次表選一場，按「設為基準」。
- 同一裝置的其他場次會自動取消基準。
- 基準會影響總覽的 Δ 欄與單場次頁的基準比較。

### 2.4 移動場次（合併裝置）

1. 在右側選取要移動的場次。
2. 上方 ComboBox 選擇目標裝置。
3. 按「移到裝置」。

完成後場次會歸到目標裝置；若目標是未識別裝置，會顯示短指紋，例如 `未識別裝置 (2715)`。

### 2.5 拆分為新裝置

1. 選取場次。
2. 在「新裝置名稱」輸入名稱。
3. 按「拆分為新裝置」。

會建立新的 DeviceId，並將該場次移到新裝置。

### 2.6 裝置覆寫

手動移動或拆分時，`session.json` 會設定：

```json
{
  "deviceId": "dev-...",
  "deviceName": "未識別裝置",
  "deviceOverridden": true
}
```

`deviceOverridden = true` 表示**中繼資料的裝置名稱優先於 ref.txt**。  
這樣把場次移到「未識別裝置」時，不會又被 ref.txt 的原始裝置名稱拉回去。

## 3. 場次比較頁

### 3.1 選擇場次

- 左側清單可勾選任意場次。
- 預設選取：
  - 每台裝置的基準。
  - 每台裝置最近的非基準場次。
  - 若該裝置沒有基準，選最近兩場。

### 3.2 選擇比較基準

- 上方「基準」ComboBox 可選擇任一場次（包含跨裝置）。
- 預設為第一個有 `isBaseline` 的場次；沒有則選目前選取的第一場。
- 所有 Δ 都以這個基準計算。

### 3.3 比較表

欄位：

- 場次、裝置、開始
- CPU 平均、ΔCPU、CPU 最高
- RAM 平均、ΔRAM、RAM 最高
- 磁碟峰值、網路峰值
- 辨識、Δ辨識
- 完整率、警告
- 基準 `★`

顏色：

- ΔCPU／ΔRAM／Δ辨識：變高紅色、變低綠色。
- 基準列顯示「基準」。

## 4. 單場次頁新增

### 4.1 基準徽章與比較

- 若該場次是基準，標頭顯示 `★ 基準場次`。
- 標頭下方顯示：
  - `此場次為基準`，或
  - `vs 基準 <場次>：CPU +x.x% ・ RAM +x.xx GB ・ 辨識 +x ms`。
- 「設為基準」按鈕可直接設定。

### 4.2 備註與標籤

在任務統計下方：

- `備註`：多行文字。
- `標籤`：以逗號分隔。
- `儲存`：寫入 `session.json` 的 `notes` 與 `labels`。
- 儲存後狀態顯示「已儲存」。

## 5. 中繼資料欄位

`session.json` 新增：

| 欄位 | 說明 |
|---|---|
| `isBaseline` | 是否為該裝置的基準 |
| `deviceOverridden` | 是否手動移動／拆分，裝置名稱以中繼資料為準 |
| `notes` | 備註 |
| `labels` | 標籤陣列（原有欄位） |
| `alias` | 裝置別名（原有欄位） |

既有欄位不變，舊檔案可直接讀取。

## 6. 開發／驗收指令

```powershell
# 指定中繼資料目錄
dotnet run --project src\PerformanceAnalysis.App -- --metadata-dir "out\test-metadata"

# 直接開裝置頁
dotnet run --project src\PerformanceAnalysis.App -- --page devices

# 直接開比較頁
dotnet run --project src\PerformanceAnalysis.App -- --page compare

# 設定基準並截圖
dotnet run --project src\PerformanceAnalysis.App -- --metadata-dir "out\test-metadata" --set-baseline "20261112_150751" --screenshot "out\shots"

# 執行一組裝置操作（別名／基準／移動／拆分／備註）並截圖
dotnet run --project src\PerformanceAnalysis.App -- --metadata-dir "out\test-metadata" --demo-ops 1 --screenshot "out\shots-ops"
```

`--demo-ops` 只應用於測試資料；一般使用請從 UI 操作。

## 7. 已驗證案例

使用 10 個現有場次：

1. 將 `DESKTOP-S136SQE` 別名設為 `LAB-A`。
2. 將 `20261112_150751` 設為 LAB-A 的基準。
3. 將 `20261112_102803` 移到 `未識別裝置 (2715)`。
4. 將 `20261109_162306` 拆分為 `NEW-LAB-B`。
5. 在 `20261112_150751` 寫入備註「夜間測試」與標籤 `baseline, night`。

結果：

- 裝置數：4
- `LAB-A`：1 場，基準 `20261112_150751`
- `未識別裝置 (2715)`：2 場（102448、102803）
- `未識別裝置 (ff75)`：6 場
- `NEW-LAB-B`：1 場
- 總覽顯示基準 `★` 與 Δ 值
- 比較頁可切換基準，ΔCPU／ΔRAM／Δ辨識正常
- 備註與標籤成功寫入並顯示

## 8. 已知限制

- 裝置頁一次移動／拆分一場；多選批次操作可後續加入。
- 比較表欄位較多，視窗較窄時需水平捲動。
- 比較頁的基準是單一全域基準；總覽的基準是各裝置基準。
- 別名／裝置操作後會重新掃描，頁面選取狀態會重置。
- 尚未提供 PDF 直接輸出；HTML 報告已於 M4 提供，可用瀏覽器列印成 PDF。
