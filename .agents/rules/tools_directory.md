## 核心定位

| 目錄 | 定位 | 版控 |
| :--- | :--- | :--- |
| `src\Tools\` | **開發區**：自研工具與維護腳本的原始碼 | 受版控管理 |
| `Tools\` | **可攜執行區**：可直接複製到任何目標機台運行的成品（角色等同 `bin\`） | **不受版控**（由建置/發佈流程生成，已由 `.gitignore` 排除） |

---

## 放置位置

| 類型 | 放置位置 | 說明 |
| :--- | :--- | :--- |
| 自研工具原始碼 / 專案 | `src\Tools\<工具名稱>\` | 例如：`src\Tools\TRIOV2.VisionSimulator\` |
| 腳本原始碼（開發、維運、資料庫遷移皆含） | `src\Tools\Scripts\` | 所有腳本與種子資料的**唯一原始位置** |
| 工具啟動捷徑（外層入口批次檔） | `Tools\<工具名稱>.bat` | 使用者點擊執行的最外層入口（優先呼叫本地 `.exe`） |
| 工具執行時內部呼叫之輔助/共用腳本 | `Tools\Scripts\` | 僅放「工具在目標裝置運行時內部會呼叫」的腳本，由 `src\Tools\Scripts\` 發佈而來 |
| 可執行檔 / 專屬相依組件資料夾 | `Tools\<工具名稱>\` 或 `Tools\` | 自包含執行檔、DLL、設定檔、必要資源等 |

---

## 腳本與入口歸屬判斷

1. **開發維護專用腳本**：
   - 僅在開發、建置、測試或資料庫初始化/遷移時使用（如 Python `.py`、C# `.csx`、打包腳本）➜ **只放** `src\Tools\Scripts\`，**嚴禁**散落在 `Tools\` 根目錄。
2. **工具啟動捷徑批次檔**：
   - 為了讓使用者在目標裝置能一鍵點擊執行 ➜ 放置於 `Tools\<工具名稱>.bat`。
   - 批次檔內容必須遵循「本地 `.exe` 優先直接調用」原則，**嚴禁**使用 `dotnet run --project` 依賴開發機原始碼。
3. **執行期共用/輔助腳本**：
   - 工具在目標裝置運行時內部需要呼叫的次級腳本 ➜ 原始碼在 `src\Tools\Scripts\`，發佈副本放 `Tools\Scripts\`。
   - `Tools\Scripts\` 內的檔案視為發佈產物，**不得直接修改**；一律改 `src\Tools\Scripts\` 後再重新發佈。

## Tools\ 可攜性原則（強制）

`Tools\` 內所有檔案與目錄的存在目的，是讓使用者在**任何 Windows 目標裝置**上只需複製其中**一個或多個檔案/目錄**即可運行，且**不需額外安裝任何元件**。

1. **零安裝**：不得要求目標裝置另外安裝執行環境或 SDK（例如 .NET SDK、Python、Node.js 等）。需要的執行環境必須隨附，或以**自包含（Self-contained / Single-File）**方式建置為獨立執行檔。
2. **相依封閉與業務資料區隔**：
   - **執行環境與組件**（.exe, .dll, runtime）：必須 100% 封閉於 `Tools\` 內部，**嚴禁參照 `src\` 原始碼目錄**。
   - **目標業務資料**（.db, .log, .ini 等維護操作對象）：維護型工具允許透過命令列參數指定，或透過安全相對路徑自動探索（例如相對於執行目錄同層或上層的 `Database\` 目錄），以滿足單機現場維護需求。
3. **相對路徑**：所有內部參照一律使用相對於自身位置的路徑，不得寫死絕對路徑、磁碟機代號、機器名稱或本機使用者名稱。
4. **不依賴環境狀態**：不得依賴 PATH 環境變數、特殊登錄檔或預先註冊之全域元件。
5. **相依可辨識**：多檔案或包含外部資源的工具目錄內必須附 `DEPENDENCIES.md`，明確列出最小複製集合；單檔自包含工具則免附獨立清單檔案（見下節）。
6. **保持清爽與精簡體積**：
   - `Tools\` 根目錄只放啟動入口批次檔與必要子目錄，不放暫存檔、建置中間檔、紀錄檔、原始碼。
   - 除錯符號檔（`.pdb`）除特定遠端除錯需求外，發佈為 Release 成品時應予排除，以精簡隨身碟與機台部署體積。

## 相依清單與共用相依（強制）

「複製一或多個檔案即可運行」的前提，是每個工具的**最小相依集合**有明確定義。

### 1. 相依清單規範
- **多檔案/具專屬目錄之工具**：
  - **原始位置**：`src\Tools\<工具名稱>\DEPENDENCIES.md`（受版控）。
  - **發佈位置**：`Tools\<工具名稱>\DEPENDENCIES.md`（發佈副本，不直接修改）。
- **單檔自包含工具（Single-File / Self-contained）**：
  - 本身已內嵌所有依賴、無外部檔案相依者，**免除在 `Tools\` 根目錄發佈獨立的 `.deps.md`**（避免污染根目錄），其單檔特性與無外部相依說明直接載於 `src\Tools\<工具名稱>\README.md` 或全域的 `Tools\readme.md` 即可。

### 2. 清單必須載明的項目（多檔案工具）

| 欄位 | 說明 |
| :--- | :--- |
| 入口 | 使用者實際執行的批次檔或執行檔 |
| 專屬相依 | 僅此工具使用的檔案/目錄（相對於工具目錄） |
| 共用相依 | 與其他工具共用的檔案（相對於 `Tools\`），例如 `Scripts\Common.ps1` |
| 最小複製集合 | 完整列出需複製的所有路徑（入口 + 專屬 + 共用） |
| 目錄結構要求 | 複製後各檔案之間必須維持的相對位置 |

範例：

```markdown
# AccountTool 相依清單

- 入口：`AccountTool.bat` 或 `AccountTool\AccountTool.exe`
- 專屬相依：
  - `AccountTool\Microsoft.Data.Sqlite.dll`
  - `AccountTool\BCrypt.Net-Next.dll`
  - `AccountTool\runtimes\win-x64\native\e_sqlite3.dll`
- 共用相依：無
- 最小複製集合：
  - `AccountTool.bat`
  - `AccountTool\`
- 結構要求：`AccountTool.bat` 必須與 `AccountTool\` 資料夾置於同一層
```

### 3. 共用相依規則
1. **集中放置**：共用檔案只能放在 `Tools\Scripts\`（共用腳本）或 `Tools\Common\`（共用組件/資源），不得散落於其他位置。
2. **保持相對結構**：複製單位以 `Tools\` 為根，複製時須保留相對路徑結構，不得壓平目錄。
3. **不得隱性共用**：工具若引用共用檔案，必須列入該工具的相依清單，禁止「碰巧同目錄有就能用」的隱性相依。
4. **獨立工具優先**：自包含工具不得依賴共用檔案；若需少量共用邏輯，應於建置時直接內嵌編譯。

### 4. 異動連動與建置檢查
- **新增或修改工具**：同步更新該工具的 `DEPENDENCIES.md`，並確認清單與實際引用一致。
- **發佈檢查（建議未來實作自動化腳本如 `Build-Tools.ps1`）**：
  1. 驗證清單所列路徑皆存在於 `Tools\`。
  2. 驗證 `Tools\` 內無任何檔案或批次檔引用 `src\` 原始碼。
  3. 驗證無多餘之臨時原始碼腳本遺留在 `Tools\` 根目錄。

---

## 禁止事項

- 不得將原始碼（`.cs`, `.py`, `.csx`）、專案檔（`.csproj`, `.sln`）放入 `Tools\`。
- 不得將開發維護專用腳本放入 `Tools\` 根目錄。
- 不得讓 `Tools\` 內任何批次檔或程式碼引用 `src\` 內的任何內容（如 `dotnet run --project ..\src\...`）。
- 不得讓建置輸出散落於 `Tools\` 與 `src\Tools\` 以外的目錄。
- 建置可執行工具成品時，一律輸出到 `Tools\` 或 `Tools\<工具名稱>\`。

---

## 實作計畫的檔案異動清單

- 檔案路徑欄位必須符合上述規則。
- 凡異動 `Tools\` 之內容，須在「變更說明」註明其相依項目，並確認符合可攜性原則。
- 凡新增或修改工具，須同步確認其獨立可攜性與相依清單之正確性。
